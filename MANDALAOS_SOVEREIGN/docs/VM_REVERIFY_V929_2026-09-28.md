## Configuration change found during qualification

The first v9.2.9 boot exposed a real integration mismatch: the prior VM unit
bound unauthenticated SSE to `0.0.0.0`, which v9.2.9 correctly refuses. The
MCP service exited with the error that non-loopback SSE requires an
authentication token/PSK. Commit `26bc2f4` changes the VM service to bind
`127.0.0.1`, removes the direct QEMU port forward and firewall opening, and
documents an SSH local tunnel. The updated VM was rebuilt and booted before
recording the pass above.
